Célkitűzés

Hogyan módosít adatot egy Backend szerver?

Míg a GET végpontok csak olvasnak az adatbázisból, az INSERT, UPDATE és DELETE műveletek megváltoztatják az adatokat. Emiatt itt kulcsfontosságú a bemenet ellenőrzése (validáció), az SQL Injection elleni védelem és a pontos HTTP státuszkódok visszaküldése.

POST /szolgaltatasok 201 Created

INSERT – Létrehozás

Új rekordot szúr be a szolgaltatasok táblába a kliens JSON törzse (req.body) alapján.

  • ✓ Minden kötelező mezőt ellenőriz (400 hiba, ha hiányzik).
  • ✓ A MySQL visszaadja az új kulcsot: result.insertId.
PUT /szolgaltatasok/:id 200 OK

UPDATE – Teljes módosítás

Az URL-ben érkező :id alapján felülírja a rekord összes mezőjét.

  • ✓ Először az ID-t ellenőrzi (ervenyesId), majd az 5 mezőt.
  • ✓ Ha result.affectedRows === 0, akkor 404 Not Found.
DELETE /szolgaltatasok/:id 200 OK

DELETE – Törlés

Nem igényel JSON törzset (req.body), kizárólag az URL azonosítója alapján töröl egy sort.

  • ✓ Érvénytelen ID-nál (pl. abc vagy -1) azonnal 400.
  • ✓ Nem létező ID-nál affectedRows === 0 → 404.

1. Paraméterezett SQL (?)

A pool.execute(..., [ertekek]) külön kezeli az SQL parancsot és a felhasználói adatokat, így megakadályozza az SQL Injection támadásokat.

2. Korai visszatérés (return)

Minden hibaágnál return res.status(400)... szerepel. Ha lemaradna a return, a kód tovább futna és ERR_HTTP_HEADERS_SENT hibát dobna!

3. Központi hibakezelés

A try { ... } catch (err) { next(err); } minden váratlan adatbázis-hibát (pl. rossz idegen kulcs) a fájl alján lévő 500-as hibakezelőnek ad át.

Miért aktiv === undefined, és miért !megnevezes?
